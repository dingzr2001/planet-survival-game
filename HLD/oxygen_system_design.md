# 玩家氧气系统设计文档

## 1. 文档目的

本文档仅定义玩家自身的氧气状态，以及氧气不足时对理智值和生命值造成的影响。

本阶段不定义氧气来自哪里，也不设计玩家氧气与大气、海拔、真空、建筑、氧气瓶或防护服之间的交互。世界最终采用“含氧大气”“低氧大气”还是“完全真空”，均不影响本文的核心规则。

## 2. 设计目标

- 玩家拥有一个直观、可配置的氧气值。
- 氧气低于警戒线后，玩家持续损失理智值。
- 氧气低于危险线后，玩家在损失理智值的同时持续损失生命值。
- 氧气越少，理智与生命损失速度越快。
- 损失速率连续变化，避免跨过阈值时突然跳变。
- 规则按游戏时间结算，不受帧率影响；游戏暂停时不结算。
- 氧气状态、低氧规则和属性修改职责分离，方便以后接入任意氧气来源。

## 3. 设计范围

### 3.1 第一版包含

- 玩家当前氧气值与最大氧气值。
- 氧气值的合法范围和受控修改方式。
- 低氧导致的理智损失。
- 严重低氧导致的生命损失。
- 随氧气下降而加速的连续损耗曲线。
- 状态等级、反馈方向和测试标准。
- 为未来氧气来源预留清晰边界。

### 3.2 第一版不包含

- 大气是否含氧。
- 大气氧气浓度与玩家氧气之间的换算。
- 海拔、气压、密闭空间或真空规则。
- 氧气的自然消耗速度。
- 奔跑、睡眠、受伤等行为对耗氧速度的影响。
- 氧气瓶、防护服、制氧机或建筑供氧。
- 氧气恢复条件和恢复速度。
- 血氧、肺部储氧等额外生理模拟。

上述系统未来只能通过玩家氧气的公开修改接口影响当前值，不能绕过氧气状态直接实现另一套低氧伤害规则。

## 4. 核心数据

### 4.1 玩家氧气

玩家氧气使用与现有生存属性一致的数值形式：

- `CurrentOxygen`：当前氧气值。
- `MaximumOxygen`：最大氧气值。
- `NormalizedOxygen`：归一化氧气比例，计算结果限制在 `[0, 1]`。

`NormalizedOxygen = MaximumOxygen <= 0 ? 0 : Clamp01(CurrentOxygen / MaximumOxygen)`

第一版建议默认最大值为 `100`。阈值和伤害公式统一使用归一化比例，因此未来改变最大氧气值时不需要同步修改所有规则。

氧气值必须由自身领域对象维护不变量：

- 当前值不得小于 `0`。
- 当前值不得高于规则允许的最大值。
- 外部系统只能通过具有语义的方法增加、消耗或设置氧气，不能直接修改字段。
- 氧气变化时发布事件，为低氧规则和未来的 HUD 反馈预留订阅入口。

### 4.2 状态分区

第一版建议使用以下默认分区：

| 氧气比例 | 状态 | 理智影响 | 生命影响 |
| --- | --- | --- | --- |
| `O >= 50%` | 安全 | 无 | 无 |
| `20% <= O < 50%` | 低氧 | 持续损失，氧气越少速度越快 | 无 |
| `0% <= O < 20%` | 严重低氧 | 持续损失，氧气越少速度越快 | 持续损失，氧气越少速度越快 |

进入严重低氧区后，理智损失不会停止；生命损失是在理智损失之上追加的惩罚。理智归零也不会阻止低氧直接扣除生命。

## 5. 数值规则

### 5.1 默认配置

| 参数 | 默认值 | 说明 |
| --- | ---: | --- |
| 理智损失阈值 | `0.50` | 氧气低于 50% 开始损失理智 |
| 生命损失阈值 | `0.20` | 氧气低于 20% 开始损失生命 |
| 最大理智损失速率 | `30 / 游戏小时` | 氧气为 0 时的理智损失速率 |
| 最大生命损失速率 | `60 / 游戏小时` | 氧气为 0 时的生命损失速率 |
| 理智曲线指数 | `1.5` | 轻度低氧较缓，接近无氧时明显加速 |
| 生命曲线指数 | `1.5` | 刚进入危险区时保留一定反应时间 |

这些数值仅作为第一轮可玩性基准。氧气本身的消耗速度尚未确定，因此目前无法最终判断每个阶段在现实时间中能持续多久。

### 5.2 计算公式

设：

- `O`：当前归一化氧气比例，范围 `[0, 1]`。
- `Ts`：理智损失阈值。
- `Th`：生命损失阈值。
- `Ps`、`Ph`：理智与生命曲线指数。
- `RsMax`、`RhMax`：理智与生命最大损失速率。
- `dt`：本次结算经过的游戏小时数。

理智低氧严重度：

`Ss = Clamp01((Ts - O) / Ts)`

生命低氧严重度：

`Sh = Clamp01((Th - O) / Th)`

本次属性损失：

`SanityLoss = RsMax * Pow(Ss, Ps) * dt`

`HealthLoss = RhMax * Pow(Sh, Ph) * dt`

最终分别向玩家应用 `-SanityLoss` 与 `-HealthLoss`。氧气等于或高于对应阈值时，严重度为 `0`，不会产生损耗。

采用幂函数是因为它连续、参数少且容易测试。指数大于 `1` 时，刚进入低氧区的惩罚较轻，氧气越接近 `0`，损失增长越明显。

### 5.3 默认参数示例

以下结果经过四舍五入，仅用于展示曲线：

| 氧气比例 | 状态 | 理智损失/游戏小时 | 生命损失/游戏小时 |
| ---: | --- | ---: | ---: |
| 100% | 安全 | 0 | 0 |
| 50% | 安全边界 | 0 | 0 |
| 40% | 低氧 | 约 2.7 | 0 |
| 30% | 低氧 | 约 7.6 | 0 |
| 20% | 严重低氧边界 | 约 13.9 | 0 |
| 10% | 严重低氧 | 约 21.5 | 约 21.2 |
| 0% | 氧气耗尽 | 30 | 60 |

## 6. 结算与边界规则

- 仅当 `elapsedGameHours > 0` 时结算低氧影响。
- 游戏暂停时不结算低氧导致的理智或生命损失；氧气值本身是否变化由未来的氧气消耗规则决定，不在本文定义。
- 氧气值由氧气领域对象限制在 `[0, MaximumOxygen]`。
- 最大氧气为 `0` 时，归一化氧气按 `0` 处理。
- 阈值必须满足 `0 < 生命阈值 <= 理智阈值 <= 1`。
- 最大损失速率和曲线指数必须大于或等于 `0`。
- `NaN`、无穷值或其他非法输入不得静默进入公式，应拒绝本次操作并输出带上下文的开发日志。
- 理智与生命由现有 `Vital` 负责限制合法范围，低氧规则不得直接修改内部字段。
- 玩家死亡后停止应用新的属性变化，沿用 `PlayerSurvival` 的死亡语义。
- 固定氧气值下，一次较大时间步与多个小时间步的累计结果应在浮点误差范围内一致。
- 若氧气在较大时间步中持续变化，氧气驱动方应拆分时间步；低氧规则不推测两次输入之间的变化过程。
- 低氧直接生命损失与现有“理智归零后扣生命”属于不同伤害来源。本文默认两者可以叠加，最终仍需结合游戏节奏调优。

## 7. 氧气变化接口

氧气状态至少应提供以下语义操作，具体签名在实现阶段确定：

- 消耗指定数量的氧气。
- 恢复指定数量的氧气。
- 将氧气设置为经过验证的指定值。
- 查询当前值、最大值和归一化比例。
- 在当前值发生实际变化后发布一次事件。

这些接口只负责维护氧气状态，不判断调用者是大气、真空、防护服、氧气瓶还是剧情事件。

建议将未来系统的调用方向固定为：

`外部氧气来源或消耗规则 -> 玩家氧气状态 -> 低氧影响规则 -> 理智与生命`

这样，无论后续选择何种世界设定，都只需要替换氧气的来源与消耗规则，不需要重写低氧伤害逻辑。

## 8. 恢复规则

氧气上升到对应阈值后，新的低氧损耗立即停止。已经失去的理智与生命不会因为氧气恢复而自动返还，应由休息、医疗、食物或其他玩法恢复。

本文不规定氧气何时恢复。未来可以由补给品、设备、安全区域或其他机制调用氧气恢复接口。

## 9. 未来工作：玩家反馈

本节描述期望的最终体验，不属于当前氧气系统的实现范围和验收要求。目前只需保证氧气状态和低氧结果可被其他模块读取，并发布必要的状态变化事件。开发阶段可使用 Inspector、调试面板或日志观察氧气与损耗结果。

当基础规则稳定且 UI、音效与后处理资源具备后，再分阶段实现以下反馈。

### 9.1 HUD

- 氧气条显示当前值或百分比，并与其他生存属性保持一致的视觉语言。
- 氧气不低于 50%：不显示额外警告。
- 氧气低于 50%：显示低氧警告，理智条增加持续损失反馈。
- 氧气低于 20%：警告升级为危险状态，生命条增加持续伤害反馈。
- 氧气继续下降时，警告强度、声音频率或屏幕效果可随严重度增强。
- 不能只使用颜色表达危险，还应配合图标、文字、动画或声音。
- 警告状态可在恢复阈值上增加少量仅用于表现的迟滞，避免数值在边界附近变化时闪烁；迟滞不得影响实际伤害计算。

### 9.2 音画反馈

建议按严重度逐步叠加呼吸急促、耳鸣、暗角或轻微失焦。表现层只读取氧气比例和严重度，不自行复制损耗公式。

持续音效、Tween 与后处理效果必须在对象禁用、玩家死亡或场景切换时停止。强烈镜头晃动和高频闪烁不作为必要反馈，并应允许玩家降低或关闭不适效果。

### 9.3 建议实施顺序

1. 氧气条、百分比和低氧文字警告。
2. 理智与生命条的持续损失提示。
3. 呼吸声、警报声及危险等级变化。
4. 暗角、失焦等后处理效果。
5. 无障碍选项与效果强度设置。

每一步均应独立可关闭，不应让反馈层成为氧气规则运行的必要依赖。

## 10. 建议技术设计

### 10.1 职责划分

- `OxygenVital` 或通用 `Vital` 实例：维护玩家氧气当前值、最大值和变化事件。
- `HypoxiaRule`：普通 C# 规则对象，根据归一化氧气和游戏时间计算严重度、理智损失与生命损失。
- `PlayerOxygen`：Unity 生命周期与场景引用桥接，对外提供受控的氧气修改入口。
- `PlayerHypoxia`：按游戏时间调用规则，并通过 `PlayerSurvival.Apply` 应用理智与生命变化。
- 未来的 HUD/表现组件：订阅氧气与危险等级变化，仅负责显示，不属于当前实现范围。
- 未来氧气驱动方：决定氧气如何消耗或恢复，不属于本设计。

低氧公式应位于可独立进行 Edit Mode 测试的普通 C# 类中。`MonoBehaviour` 只负责生命周期、引用装配和表现桥接。

### 10.2 建议结果模型

规则计算结果建议包含：

- 归一化氧气比例。
- 理智低氧严重度。
- 生命低氧严重度。
- 本时间步理智损失。
- 本时间步生命损失。
- 离散危险等级：`Safe`、`LowOxygen`、`Critical`。

离散危险等级为未来 UI 和音效提供稳定输入，连续严重度服务于属性损失以及未来的效果强度。调用方不得根据危险等级重新实现另一套损耗公式。

### 10.3 配置方式

阈值、最大损失速率和曲线指数建议由玩家生存配置承载，而不是放入星球或大气配置。

配置加载后应创建运行时只读规则对象，避免游戏过程中无意修改共享资产。氧气的自然消耗、恢复和外部来源将在对应玩法确定后使用独立配置。

### 10.4 与现有系统的关系

- 当前 `VitalType` 没有 `Oxygen`。实现时可以增加 `Oxygen`，并在 `SurvivalStats` 中增加对应 `Vital`；这属于公共枚举和序列化结构变更，需要检查 HUD、存档与所有 `switch`。
- 理智与生命继续使用现有 `SurvivalStats` 和 `PlayerSurvival.Apply` 修改。
- 现有 `SurvivalDecay` 已负责饱食、口渴及属性归零惩罚。低氧建议使用独立规则与组件，避免继续扩大其职责。
- 现有 `AtmosphereModel` 和 `EnvironmentSample.OxygenRatio` 不接入本系统，也不在本阶段修改。
- 无论以后选择哪种世界设定，本文的玩家氧气状态与低氧影响规则保持不变；具体接入方式另行设计。

## 11. 测试建议

### 11.1 Edit Mode

- 氧气高于、等于和刚低于 50% 时，理智损失符合阈值规则。
- 氧气高于、等于和刚低于 20% 时，生命损失符合阈值规则。
- 氧气为 0 时达到配置的最大理智和生命损失速率。
- 氧气从高到低时，两种损失速率单调不减。
- 氧气恢复到阈值以上后，新的对应损失立即为 0。
- 当前氧气无法被设置为负数或超过允许最大值。
- 最大氧气为 0、时间步为 0 或负数时结果明确且稳定。
- `NaN` 与无穷输入被拒绝并产生明确诊断。
- 固定氧气下，一次结算 1 游戏小时与十次结算 0.1 游戏小时的累计结果一致或在浮点误差范围内一致。
- 非默认阈值、速率和指数配置正确生效。
- 非法配置在创建规则时被拒绝或规范化，并产生明确诊断。

### 11.2 Play Mode

- 通过测试入口修改玩家氧气后，危险等级和属性变化正确更新。
- 氧气恢复到安全区后损耗立即停止，已经损失的属性不会自动恢复。
- 暂停时不结算低氧影响；恢复后不补扣暂停期间时间。
- 时间倍率只改变现实时间中的表现速度，不改变每游戏小时损失量。
- 严重低氧与理智归零惩罚同时存在时，生命损失正确叠加且不会重复注册回调。
- 玩家死亡、禁用或切换场景后，低氧结算停止。

### 11.3 手工验收

- 直接将氧气设置为 50%、40%、30%、20%、10% 和 0%，确认结果与示例曲线相符。
- 在 50% 和 20% 附近反复改变数值，确认属性损失连续且状态等级切换正确。
- 使用临时调试入口控制氧气即可，不需要先实现任何大气或真空规则。

## 12. 验收标准

- 氧气不低于理智阈值时，不因低氧损失理智或生命。
- 氧气低于理智阈值时开始损失理智；低于生命阈值时同时开始损失生命。
- 在其他参数相同的情况下，氧气越低，每游戏小时的损失量越大或相等，且阈值处没有数值跳变。
- 氧气为 0 时，损失速率不超过配置的最大值。
- 氧气恢复至对应阈值后立即停止新增损耗，但不自动恢复已损失属性。
- 结果与帧率无关，暂停期间不结算，时间倍率下每游戏小时结果一致。
- 氧气状态、低氧规则和玩家属性之间职责清楚，核心公式可在 Edit Mode 独立验证。
- 核心规则不依赖大气、海拔或真空设定。
- 非法输入和缺失引用不会造成未捕获异常、负属性或静默失效。
- HUD、音效和后处理反馈不属于当前验收范围；缺少这些反馈不阻碍基础氧气系统完成。

## 13. 待产品确认项

以下内容不影响低氧影响规则的设计，但在实现完整氧气循环前需要确认：

1. 世界采用含氧大气、低氧大气还是完全真空。
2. 玩家氧气是持续消耗的资源，还是只在特定区域或状态下改变。
3. 氧气消耗以现实秒、游戏分钟、游戏小时还是玩家行为为基础。
4. 安全区、氧气瓶、装备或设备如何恢复氧气。
5. 是否允许装备改变氧气最大值、损耗阈值或低氧伤害速率。
6. 50% 与 20% 两个默认阈值是否符合最终氧气消耗节奏。
7. 低氧直接生命损失是否与“理智归零后扣生命”叠加；本文暂时按叠加设计。

## 14. 完成定义

当氧气状态和低氧规则的 Edit Mode 测试通过、氧气到玩家属性的 Play Mode 链路通过、暂停和时间倍率行为正确，并确认核心代码不依赖任何大气、真空或表现层设定后，基础氧气系统可视为完成。HUD、音效和后处理反馈作为后续迭代单独验收。
