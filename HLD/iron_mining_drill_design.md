# 铁矿机设计说明

## 目标与玩家流程

铁矿机是一个 `1×1` 地表建筑，只能放在仍然存在的铁矿地形上。建造完成后，玩家靠近按 `E` 打开设备面板，可以从背包加入石油罐或取走设备内的铁矿石。设备也预留了电网、石油管道和自动矿石输出的连接接口。

基本循环：

1. 将 8 个铝合金带到铁矿地形并建造铁矿机。
2. 接入电力，或把石油罐装入设备（初始货舱提供 4 罐）。
3. 设备以 `0.25 个/秒` 生产铁矿石，优先消耗电力，没有足够电力时再消耗石油。
4. 铁矿石保存在设备内部；达到 20 个上限后立即停止，不再消耗能源。
5. 玩家手动取出，或由自动化连接以最高 `2 个/秒` 输出。

## 放置规则

- 建筑占地为一个建造格，贴图按约 `0.98` 世界单位显示，并使用底部中心锚点；裁切版贴图没有外围透明边框，视觉主体尽量铺满整个格子。
- `BuildingService` 在付费和占格之前检查占地中每个建造格的中心点。
- 每个点对应的 `TerrainSurfaceDefinition.TerrainId` 必须为 `iron`。
- 铁矿格一旦被挖空，地表回退为基础地形，矿机预览变红并返回 `BuildFailure.WrongTerrain`。
- 校验放在领域服务中，而不是只放在鼠标预览中，因此脚本、测试或未来 AI 建造也不能绕过限制。

## 运行状态与数值

`MiningDrill` 是不依赖场景对象的运行时状态，由 `BuildSite` 持有，所以玩家进入舱内再返回时，剩余燃料、缓存电量、生产进度和库存都不会丢失。

| 参数 | 默认值 |
|---|---:|
| 生产速度 | 0.25 铁矿石/真实秒 |
| 矿石库存 | 20 |
| 自动输出上限 | 2 铁矿石/真实秒 |
| 单个石油罐 | 5 石油单位 |
| 石油箱容量 | 20 石油单位 |
| 石油消耗 | 1 单位/铁矿石 |
| 电力输入缓存 | 25 能量单位 |
| 电力消耗 | 5 能量单位/铁矿石 |

生产使用浮点进度累积，只有完整的矿石才进入库存。帧长变化不会改变总产量；只为实际完成的生产进度扣除能源。设备状态分为：

- `Unpowered`：没有足够的电或石油继续生产；
- `Producing`：拥有能源且库存未满；
- `StorageFull`：库存达到上限，生产与能源消耗暂停。

## 接口与职责

- `IElectricityInput.ReceiveElectricity(float)`：电网向输入缓存送电，返回实际接收量。
- `IPetroleumInput.ReceivePetroleum(float)`：管道向内部油箱送油，返回实际接收量。
- `IItemOutput.Extract(int, float)`：传送带或矿石管道按经过时间限速取货，并通过 `OutputItem` 确认物品类型。
- `MiningDrill.LoadPetroleumItems(...)`：玩家背包石油罐到液体油箱的原子转移。
- `MiningDrill.CollectOre(...)`：按背包剩余容量安全取矿，不会因背包装不下而丢失物品。
- `MiningDrillStation`：只负责 Unity 生命周期、交互提示和打开 UI。
- `MiningDrillView`：提供加油、取矿和三种缓存状态显示，不承载生产规则。

接口直接实现在同一个矿机状态对象上。未来电网、液体管道和传送系统只需持有相应的小接口，不需要依赖 UI、`MonoBehaviour` 或矿机内部字段。

## 资源与配置

- `IronMiningDrill.asset`：所有产速、容量和能源换算参数。
- `IronMiningDrillBuildable.asset`：建造成本、占地、建造时间和世界贴图。
- `PetroleumCanister.asset`：玩家可携带的石油燃料物品。
- `IronMiningDrill.png`：由所附矿机图生成的透明紧边版本，底部中心为世界锚点。
- `IronOre.png`：使用所附铁矿石图作为物品图标。

这些数值均保存在 ScriptableObject 中；平衡调整不需要修改生产代码。

## 验证重点

Edit Mode 测试覆盖石油生产、电力优先级、满仓停机、背包转移、自动输出限速、非铁矿地形拒绝以及挖空铁矿地形拒绝。仍建议在 Unity Play Mode 中手工确认一次：建造预览颜色、贴图占格、面板按钮、进入/离开着陆舱后的状态保持，以及未来管线模型与格子边缘的视觉衔接。
