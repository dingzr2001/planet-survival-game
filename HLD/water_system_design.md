# 玩家水资源系统简要设计文档

## 1. 目标与范围

本系统为玩家提供可携带、可补充和可饮用的水资源，并让水量与口渴值形成清晰的生存循环。

第一版包含：

- 固定容量的个人水瓶。
- 着陆舱有限储水资源。
- 生活层补水终端及专用补水界面。
- 物品栏中的水瓶显示与饮用操作。
- 水量在生活层、物资层和舱外场景之间保持。

第一版不包含饮水动画、音效、水质、不同液体类型、容器替换、世界掉落和永久存档。

## 2. 体验设计

补水终端设置在生活层厨房水槽附近，水源来自物资层的着陆舱储水罐，通过舱内管线供应。

采用生活层补水的原因是饮水属于高频生存行为。若每次补水都强制前往物资层，重复上下楼会形成较重的通勤负担；生活层终端保留了空间合理性，同时让玩家能在休息、进食等生活流程中顺手补水。

## 3. 核心数值

| 参数 | 数值 | 说明 |
| --- | ---: | --- |
| 水瓶容量 | `500 mL` | 固定容量，不可升级 |
| 初始水瓶水量 | `0 mL` | 玩家需主动学习补水流程 |
| 单次饮用量 | `100 mL` | 一瓶可饮用 5 次 |
| 单次口渴恢复 | 最大口渴值的 `20%` | 五次恰好对应完整口渴条 |
| 着陆舱初始储水 | `20 L` | 约可灌满 40 瓶 |
| 口渴自然下降 | `3 / 游戏小时` | 沿用现有生存规则 |

一次饮用约抵消 6.7 游戏小时的自然口渴下降；一整瓶约覆盖 33 个游戏小时。按照 30 天救援周期估算，纯饮水需求约为 10.8 L，20 L 储备允许玩家犯错，也为未来烹饪等用水系统预留空间。

## 4. 状态与规则

### 4.1 个人水瓶

- 水量始终限制在 `[0, 500] mL`。
- 水瓶属于固定随身装备，不参与普通物品堆叠，不可丢弃，也不占普通背包容量。
- 每次成功饮用必须完整消耗 `100 mL`，不支持部分饮用。
- 水量不足 `100 mL` 时拒绝饮用，不改变水量或口渴值。
- 口渴已满或玩家死亡时拒绝饮用，防止误耗资源。
- 口渴恢复结果受属性最大值限制，不会超过上限。

### 4.2 着陆舱储水罐

- 储水量不得为负。
- 灌装量同时受水瓶剩余容量和储水罐剩余水量限制。
- 转移必须保持液体守恒，且在通知 UI 前同时提交水瓶和储水罐的新状态。
- 新游戏或重新开始游戏时恢复为 `20 L`；普通场景切换不重置。

## 5. 玩家交互

### 5.1 补水

1. 玩家靠近生活层水槽区域。
2. HUD 显示 `Press E to use the water dispenser`。
3. 按 `E` 打开专用补水界面，并暂时锁定人物移动和重复交互。
4. 界面显示水瓶当前量、500 mL 上限、剩余可装量和舱内储水余量。
5. 点击 `FILL BOTTLE`，系统尽可能灌满水瓶并显示实际转移量。
6. 关闭界面后恢复玩家控制。

### 5.2 饮用

- 快捷栏最左侧为固定水瓶格，显示水瓶贴图、当前毫升数和快捷键 `Q`。
- 按 `Q` 或点击快捷水瓶格可直接饮用。
- 打开背包后，水瓶作为第一格显示；选中后可点击 `Drink`。
- 成功或失败后在快捷栏上方显示短暂反馈。

## 6. 技术职责

- `LiquidContainer`：维护容量、水量、消耗与守恒转移规则，不依赖 UI。
- `GameSessionState`：拥有本局水瓶和着陆舱储水状态，负责跨场景生命周期。
- `PlayerWaterBottle`：执行饮用用例，将 100 mL 水转换为 20% 口渴恢复。
- `LandingPodWaterDispenser`：连接世界交互、储水罐、水瓶和补水界面。
- `WaterRefillView`：展示补水信息并接收灌装确认。
- `InventoryView`：将水瓶作为固定装备显示，并提供快捷与背包饮用入口。

水瓶本体与瓶内液体分离：水瓶不会像普通消耗品一样在使用后从背包删除，只有其内部水量发生变化。

## 7. 验收标准

- 新游戏开始时水瓶为空，容量显示为 `500 mL`。
- 水瓶同时出现在快捷栏和完整背包中，贴图与当前水量正确。
- 补水界面能正确显示并更新水瓶与储水罐余量。
- 满罐灌装空瓶后，水瓶增加 500 mL，储水罐减少 500 mL。
- 每次成功饮用减少 100 mL，并恢复最大口渴值的 20%。
- 满口渴、死亡或水量不足时饮用失败且不消耗水。
- 水瓶水量在生活层、物资层和舱外之间保持。
- 重新开始游戏后，水瓶和着陆舱储水恢复初始状态。
- 所有边界路径均不会产生负水量、超容量或重复消耗。

## 8. 后续扩展

未来若加入烹饪、种植、制氧或净水系统，应共同消耗同一个着陆舱储水状态，而不是各自维护独立水量。若增加不同液体或可更换容器，再将当前单一水容器扩展为带液体类型的通用容器模型。
