# 区块资源加载设计文档

## 1. 文档目的

本文档定义地表资源节点在无限世界中的分布规则与加载策略，即“哪里有资源”和“什么时候把它们放进场景”。

本文档不定义资源节点自身的采集流程、产出表和背包交互，这些内容见 `implementation_plan.md` 阶段 5 与 `inventory_design.md`。地下资源、资源再生和存档同样不在本文范围内。

## 2. 背景

第一版原型把资源一次性铺在出生点的 48×48 逻辑地图内：整图固定 136 个节点，密度约 1 个 / 16.9 m²。地面表现层（`GridTerrainView`）实际上是跟随玩家的无限平面，因此玩家一旦走出出生区域，世界就完全空了，同时出生地又密得不像野外环境。

本设计要解决两个问题：世界处处有资源，且整体密度大幅下降。

## 3. 设计目标

- 玩家走到任何地方都可能遇到资源，不存在“资源边界”。
- 资源密度显著低于原型，探索需要移动而不是原地打转。
- 相同世界种子产生完全可复现的资源分布，与玩家的行走路线和访问顺序无关。
- 常驻场景对象数量有上限，不随探索距离增长。
- 已采集的节点不因为离开再回来而复活。
- 分布规则可独立于 Unity 运行时进行 Edit Mode 测试。

## 4. 设计范围

### 4.1 包含

- 世界的区块划分方式与区块坐标。
- 单个区块内的资源数量、种类和位置规则。
- 区块的加载、卸载半径与滞回策略。
- 已采集节点在区块卸载后的记忆方式。
- 出生点净空规则。

### 4.2 不包含

- 地形高度、生物群系和区块之间的地貌差异。
- 资源随时间再生或季节变化。
- 资源分布的持久化存档（见第 10 节）。
- 区块内的敌人、遗迹、结构物等非资源内容。
- 地形网格本身的分块（当前仍是跟随玩家的单一圆盘网格）。

## 5. 核心概念

### 5.1 区块

区块是无限 XZ 平面上边长固定的正方形，由整数坐标 `(X, Z)` 寻址。区块 `(0, 0)` 从世界原点向 +X、+Z 延伸，因此原点另一侧的区块坐标为负，世界坐标到区块坐标使用向下取整除法。

区块只是资源生成与加载的划分单位，不参与地形表现，玩家也感知不到它的边界。

### 5.2 确定性规划

每个区块的资源布局由 `世界种子` 与 `区块坐标` 经 FNV-1a 哈希得到的独立随机种子决定。这带来三条重要性质：

- 任何区块都可以被单独计算，不需要先算出它的邻居，也不需要按顺序生成。
- 卸载后重新计算得到完全相同的结果，因此卸载是安全的。
- 相邻区块的种子经过充分混合，不会因为坐标相邻而产生相似布局。

世界种子取 `TerrainGenerationSettings.Seed + ResourceSpawnSettings.SeedOffset`，因此调整资源分布时不需要改动地形种子。

### 5.3 密度而非数量

资源配置从“整张地图多少个”改为“每个区块平均多少个”。密度允许为小数：整数部分是该区块保底生成的数量，小数部分按概率决定是否多生成一个。密度小于 1 表示该资源只出现在一部分区块中，这是让稀有资源自然分布的主要手段。

## 6. 生成规则

对每个区块依次执行：

1. 由世界种子与区块坐标计算该区块的随机种子。
2. 对每个资源条目，按密度解析出本区块的节点数量：`floor(密度) + (random < frac(密度) ? 1 : 0)`。
3. 为每个节点在区块范围内均匀取点，若与本区块已确定的节点距离小于最小间距则重取，最多 12 次；超出次数则放弃该节点。
4. 生成时跳过落在出生点净空半径内的位置，以及已被采集过的位置。

拒绝采样使用固定次数预算而不是无限重试，保证稀疏区块的规划成本恒定；在当前参数下这个上限从未被触发（见第 9 节）。

### 6.1 默认参数

| 参数 | 默认值 | 说明 |
| --- | ---: | --- |
| 区块边长 | `32 m` | 面积 1024 m² |
| 加载半径 | `2` 区块 | 常驻 5×5 区块，约 160×160 m |
| 卸载余量 | `1` 区块 | 环距离超过 3 才卸载 |
| 最小间距 | `4 m` | 仅约束同一区块内部 |
| 出生点净空半径 | `3 m` | 设为 0 即关闭 |
| 石头密度 | `2.5` / 区块 | |
| 残骸密度 | `1.5` / 区块 | |
| 植物密度 | `2.5` / 区块 | |

### 6.2 密度结果

| | 原型 | 当前 |
| --- | --- | --- |
| 覆盖范围 | 仅出生点 48×48 区域 | 全世界 |
| 数量 | 固定 136 个 | 平均 6.5 个 / 区块（实测 5–8） |
| 密度 | 1 个 / 16.9 m² | 1 个 / 157 m²（约 1/9.3） |
| 常驻节点 | 136 | 约 163 |

## 7. 加载与卸载

流式加载以玩家所在区块为中心：

- 玩家跨入新区块时，加载半径内所有尚未加载的区块，卸载环距离超过 `加载半径 + 卸载余量` 的区块。
- 玩家未跨区块时不做任何工作，只比较一次区块坐标。
- 卸载余量提供滞回：沿区块边界来回走动不会反复加载与销毁同一批对象。

### 7.1 已采集节点的记忆

区块卸载前，逐个检查其节点的耗尽状态，把已采集节点的 `(区块坐标, 规划索引)` 记入集合；该区块重新加载时跳过集合中的位置。

规划索引要求跳过逻辑不改变列表顺序，因此净空过滤与已采集过滤都在遍历中按索引跳过，不重排规划结果。没有定义的资源条目按密度 0 处理，保证增删条目不会整体移位。

集合只保存已采集节点，规模随玩家实际采集量增长，而不是随探索面积增长。

## 8. 职责划分

| 类型 | 职责 | 依赖 Unity |
| --- | --- | --- |
| `ChunkCoordinate` | 区块寻址、世界坐标换算、环距离 | 否 |
| `ChunkResourcePlanner` | 由种子与区块坐标规划布局 | 否 |
| `ChunkResourcePlacement` | 单个规划结果（条目索引 + 世界坐标） | 否 |
| `ResourceSpawnSettings` | 区块尺寸、加载半径、间距、净空、各资源密度 | 配置资产 |
| `ResourceChunkStreamer` | 跟随目标加载/卸载区块，记忆已采集节点 | 是 |
| `ResourceNodeFactory` | 构建单个资源节点对象 | 是 |
| `GameBootstrap` | 装配流式加载组件，注入种子与出生点 | 是 |

分布规则集中在不依赖 Unity 的 `ChunkResourcePlanner` 中，`MonoBehaviour` 只负责生命周期与对象管理。表现层与采集逻辑不感知区块的存在。

## 9. 边界与不变量

- 区块边长必须为正，`ChunkResourcePlanner.Plan` 对非正值抛出 `ArgumentOutOfRangeException`。
- 密度列表为空时返回空规划，不产生日志噪音。
- 每个规划位置都落在本区块范围内。
- 同一区块内任意两个节点的距离不小于最小间距。**跨区块边界不保证间距**：各区块独立规划，低密度下偶尔会出现两个节点靠得较近。
- 出生点净空中心在装配时固定，不跟随玩家移动，因此区块重建结果保持一致。
- 净空半径内不生成节点，玩家不会在开局与节点碰撞盒重叠。
- 相同世界种子下，任意区块的规划结果与访问时间、访问次数和访问顺序无关。

## 10. 已知限制与未来工作

- **跨区块间距**：彻底消除需要规划时读取 8 个邻居的结果，成本约 9 倍，当前密度下收益不足。
- **无持久化**：已采集节点集合只存在于本次运行的内存中，重开游戏后全部复原。存档阶段应把它与世界种子一并持久化。
- **同步加载**：跨区块时一次性创建整列区块的节点对象。当前每区块约 6 个节点，开销可忽略；若未来密度或区块内容显著增加，应改为分帧或对象池。
- **均匀分布**：所有区块使用同一套密度，世界各处统计上一致。生物群系、资源富集区或危险区域需要在密度之上引入区域调制。
- **地形仍未分块**：地形表现层是跟随玩家的单一网格，与资源区块相互独立。

## 11. 测试与验证

### 11.1 Edit Mode

`ChunkResourcePlannerTests` 覆盖：

- 相同区块与种子产生完全相同的规划。
- 所有位置落在本区块范围内（含负坐标区块）。
- 同一区块内满足最小间距。
- 常规密度下每个区块都至少有一个节点。
- 小数密度在多个区块间正确分摊：均值符合配置，且存在空区块。
- 空密度列表返回空结果，非正区块边长抛出异常。

### 11.2 手工验收

- 朝任意方向持续行走，资源应始终稀疏出现，不存在空白边界。
- 采集若干节点后走远再折返，已采集的节点不应复活。
- 沿区块边界来回走动，Hierarchy 中的区块对象数量应保持稳定。
- 开局位置周围 3 m 内应为空地。

### 11.3 数值验证记录

规划器不依赖 Unity，可用独立 .NET 程序直接编译源码验证统计特性。首次实现时的验证结果：

- 3600 个区块：均值 6.513 个 / 区块，最少 5、最多 8，无空区块；位置全部在界内，间距全部满足，无节点因采样次数耗尽被放弃。
- 密度 0.5 时 400 个区块：均值 0.5，恰好 200 个区块为空。
- 5000 个世界种子：出生点 1 m 内存在节点的种子由 91 个（1.82%）降为 0 个，净空平均只移除 0.177 个节点。

## 12. 验收标准

- 任意方向探索都能持续遇到资源，且不存在资源密集的出生区域。
- 相同世界种子下，同一位置的资源布局可复现。
- 常驻资源节点数量不随探索距离增长。
- 已采集节点在区块重新加载后不复活。
- 玩家出生位置不与任何资源节点重叠。
- 分布规则的核心逻辑可在 Edit Mode 中独立验证，不需要进入场景。
