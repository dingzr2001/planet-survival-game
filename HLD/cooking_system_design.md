# 烹饪系统简要设计文档

## 1. 目标与定位

烹饪把野外采集或仓储中的生鲜原料转化为可食用的成品料理，是"资源 → 生存补给"链条中的加工环节。

当前版本要求：

- 玩家靠近烹饪器具时按 `E` 打开烹饪界面。
- 界面展示该器具能做、且当前背包原料足够的全部料理。
- 制作消耗原料并等待一段真实时间，完成后产出对应食品。
- 支持批量制作：一次投入多份原料，按份数成倍计时并成倍产出。
- 首个内容为烤土豆：土豆在生活舱烤箱烤制而成。

烹饪复用既有的 `CraftingRecipe` 与条件系统，只在其上补充"耗时"这一维度，不另起一套配方格式。

## 2. 核心规则

- **条件驱动**：配方通过 `RequiredConditionIds`（如 `station.oven`）声明所需器具；器具通过 `ProvidedConditionIds` 声明自己满足哪些条件。器具菜单只展示条件被完全覆盖的配方，因此烤箱配方不会出现在未来的篝火上。
- **开火即扣料**：点击制作时立刻扣除整批原料，避免玩家反复开关界面刷取物品。
- **成品留在器具内**：计时结束后产物暂存于器具，玩家点击"领取"才进入背包。背包已满时领取失败，成品仍保留在器具中，不会被销毁。
- **取消可退料**：制作中途取消，整批原料原样退回背包；已完成的成品不能取消，只能领取。
- **一炉一批**：每个器具同时只处理一批。处于制作中或待领取状态时不能开始新的制作。
- **跨场景保持**：烹饪进度存放在 `GameSessionState` 中，按器具 ID 索引。玩家下到货舱再回来，烤箱仍在烤制。

## 3. 核心数值

| 参数 | 默认值 | 说明 |
| --- | ---: | --- |
| 烤土豆配方 | 土豆 ×1 → 烤土豆 ×1 | 单份配比 |
| 单份耗时 | `30 s` | 默认日长下约 1.2 个游戏小时 |
| 批量耗时 | `30 s × 份数` | 线性叠加，不提供批量折扣 |
| 烤土豆热量 | `300 kcal` | 按 `25 kcal = 1 点饱食度` 换算为 `12` 点饱食度 |
| 精神值恢复 | `4` | 低于能量棒的 `6`，定位为日常口粮 |
| 单个容量占用 | `1` | 与土豆一致 |
| 最大堆叠 | `20` | 与土豆一致 |
| 开局土豆数量 | `12` | 存放于登陆舱一层物资仓 |

土豆本身 `CanUse = false`、热量为 `0`，必须烹饪后才能食用；这是原料与成品的唯一区分方式，不额外引入"生食"标记。

## 4. 模块职责

| 类型或资源 | 职责 |
| --- | --- |
| `CraftingRecipe` | 配方本体：输入、输出、所需条件、单份耗时 `DurationSeconds` |
| `CookingStationDefinition` | 器具配置：器具 ID、显示名、提供的条件、可做的配方列表 |
| `CookingProcess` | 单个灶位的状态机：扣料、计时、领取、取消、批量份数 |
| `CookingState` | `Idle` / `Cooking` / `Ready` 三态 |
| `CookingStation` | `IInteractable` 实现：驱动计时、生成交互提示、打开界面 |
| `CookingStationBinding` | 把"配置 + 灶位 + 界面"三者打包，供场景构建器一次传入 |
| `CookingView` | 烹饪面板：菜单筛选、原料图标、批量控件、进度与领取 |
| `GameSessionState` | 按器具 ID 持有灶位状态，重开游戏时清空 |
| `Inventory.ApplyTransaction` | 原子完成扣料与产出，失败时不产生部分结果 |

领域层（`Cooking/Domain`）不引用任何 Unity 场景类型，可直接用 Edit Mode 单元测试覆盖；`CookingStation` 只负责生命周期与场景桥接。

## 5. 交互流程

1. 玩家在登陆舱二层（生活舱）走近厨房灶台，快捷栏上方出现 `Press E to cook at the oven`。
2. 按 `E` 打开烹饪面板，同时锁定移动、交互与背包界面。
3. 面板列出可做料理，玩家用 `−` / `+` / `MAX` 选择份数，点击 `COOK ×N`。
4. 原料立即从背包扣除，进度条开始推进；此时可关闭面板离开，烤箱继续工作。
5. 完成后提示变为 `Press E to collect Roast Potato ×N from the oven`。
6. 再次交互并点击 `COLLECT`，成品进入背包，并自动分配到空闲快捷位。
7. 在背包或快捷栏使用烤土豆，恢复饱食度与精神值。

原料初始存放在货舱物资仓，玩家需先取到背包——菜单按背包内容筛选，仓储中的原料不参与。

## 6. 界面设计

面板分左右两栏：

- **左栏（菜单）**：`READY TO COOK` 列出背包原料足够的料理；`MISSING INGREDIENTS` 灰显列出缺料的料理，让玩家知道下一步该采集什么。
- 每行结构：成品图标 → 成品名与产出数量 → **原料图标 + `已有/需要` 数字** → 总耗时 → 批量控件与 `COOK ×N`。原料用贴图而非文字表示，识别更快；鼠标悬停时在面板底部显示物品名。数量不足时原料图标变暗、数字转红。
- **右栏（灶台）**：显示当前批次的成品图标、进度条、剩余秒数，以及 `CANCEL`（制作中）或 `COLLECT`（已完成）。

批量份数按配方分别记忆，并始终夹在 `1` 到 `MaxBatches` 之间；背包原料减少时份数自动回落，不会出现点了做不了的按钮。

IMGUI 在一次绘制过程中改变控件数量会导致布局错乱，因此所有按钮点击只记录意图，等本次 `OnGUI` 走完再统一执行。

## 7. 边界与失败处理

| 情况 | 结果 |
| --- | --- |
| 原料不足 | 配方进入灰显区，`COOK` 不可点；直接调用返回 `MissingIngredients`，不扣料 |
| 器具不满足配方条件 | 配方不出现在菜单；直接调用返回 `MissingCondition` |
| 灶位忙碌 | 返回 `StationBusy`，第二批不消耗任何原料 |
| 份数小于 1 | 返回 `InvalidRecipe` |
| 领取时背包满 | 返回 `InventoryFull`，状态保持 `Ready`，成品不丢失 |
| 无成品时领取 | 返回 `NothingReady` |
| 游戏暂停 | `Time.deltaTime` 为 0，计时自然暂停 |
| 重新开始游戏 | `GameSessionState.Reset()` 清空所有灶位，原料不退还 |

**已知限制**：计时由 `CookingStation.Update` 驱动，因此只在器具所在场景加载时推进。玩家离开登陆舱去地表时，烤箱会暂停而非继续烤制。若后续需要离线推进，应改为记录完成时刻并由持久化的时钟结算。

## 8. 验收标准

- 走近生活舱灶台出现交互提示，按 `E` 打开面板；离开后提示消失。
- 背包有土豆时，`READY TO COOK` 中出现烤土豆；没有土豆时它出现在灰显区且 `COOK` 不可点。
- 原料以土豆贴图展示，并标注 `已有/需要`，不足时变红。
- 选择 3 份后，扣除 3 个土豆，总耗时显示 `90s`，完成后一次领取 3 个烤土豆。
- 制作中取消，土豆全额退回背包。
- 背包塞满时领取失败，成品仍留在烤箱，腾出空间后可正常领取。
- 下到货舱再返回，烤箱进度保持（不倒退、不重置）。
- 食用烤土豆恢复 `12` 点饱食度和 `4` 点精神值。
- 重新开始游戏后烤箱回到空闲状态。

## 9. 后续调整点

- 根据实际节奏调整耗时与热量；必要时为大批量提供时间折扣。
- 增加更多器具（篝火、微波炉）与多原料配方，验证条件系统与多原料图标行的排版。
- 支持多灶位或制作队列，让一台器具同时处理多批。
- 增加烹饪失败、烧焦或熟练度等玩法维度。
- 若需要离线烹饪，改用时间戳结算并纳入存档。
