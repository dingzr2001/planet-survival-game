# 人物背包与快捷物品栏设计文档

## 1. 文档目的

本文档定义人物背包系统与屏幕底部快捷物品栏的产品需求、交互规则、领域模型、异常处理和验收标准，用于 Unity 实现、UI/UX 设计、测试及后续存档系统接入。

## 2. 设计目标

- 玩家拥有一个总容量固定、物品数量不固定的背包。
- 每种物品按自身容量占用值消耗背包容量。
- 物品无法完整放入剩余容量时，默认拒绝本次放入，不产生部分拾取。
- 屏幕底部始终提供快捷物品栏，最多直接展示 10 个快捷项。
- 玩家可展开总背包面板，查看和管理当前拥有的全部物品。
- 总背包面板与快捷栏支持拖拽配置，并保证操作不会复制或丢失物品。
- 快捷栏与总背包面板均显示“已使用容量 / 总容量”。

## 3. 核心概念与范围

### 3.1 总背包

总背包是玩家物品数据的唯一所有者。物品的添加、移除、堆叠、使用、丢弃和容量计算均以总背包为准。

背包容量使用非负整数表示，第一版不支持小数容量。示例：总容量为 `30`，水袋单个占用 `2`，拥有 3 个水袋时占用 `6`。

### 3.2 快捷物品栏

快捷物品栏位于游戏 HUD 底部中央，默认最多显示 10 个物品项。它是总背包物品的快捷引用和顺序配置，不是独立物品容器：

- 将物品从背包面板拖入快捷栏：为该物品创建或移动快捷引用。
- 将物品从快捷栏拖回背包面板：取消快捷引用，物品仍保留在总背包中。
- 快捷栏内换位：只改变显示和快捷键顺序。
- 物品数量和容量不会因快捷栏操作发生变化。

### 3.3 第一版范围

第一版包含：容量限制、同类物品堆叠、快捷栏配置、总背包展开面板、拖拽、容量显示、使用和丢弃的接口边界。

第一版不包含：装备栏、物品重量与容量双重限制、物品旋转或俄罗斯方块式空间、背包嵌套、自动整理算法、多人同步、耐久度和不同品质实例。上述能力后续按真实需求扩展。

## 4. 功能需求

### 4.1 物品定义

每种物品应具有稳定且唯一的 `ItemId`，并至少配置：

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| 名称 | UI 展示名称 | 不得为空 |
| 图标 | 快捷栏与背包面板图标 | 缺失时显示统一占位图 |
| 单件容量 | 每一件物品占用的容量 | 大于 0 的整数 |
| 最大堆叠数 | 单个堆叠允许的最大数量 | 大于 0；不可堆叠物品设为 1 |
| 描述 | 物品详情文本 | 可为空 |
| 可使用/可丢弃 | 支持的操作能力 | 由物品定义决定 |

静态配置建议由 `ScriptableObject` 承载；运行时数量、快捷栏位置等状态不得写回配置资产。

### 4.2 容量计算

背包已使用容量按以下规则计算：

`已使用容量 = Σ（物品单件容量 × 当前数量）`

`剩余容量 = 总容量 - 已使用容量`

新增物品所需容量为：

`所需容量 = 物品单件容量 × 新增数量`

仅当 `所需容量 <= 剩余容量` 时允许添加。默认添加操作具有原子性：请求数量不能全部装入时，整次操作失败，原有物品和容量保持不变。

示例：总容量 `30`，已使用 `27`；单件容量为 `2` 的物品即使只添加 1 件也应被拒绝。

### 4.3 添加与堆叠

- 添加物品时，优先补充未达到最大数量的已有同类堆叠，再创建新堆叠。
- 堆叠数量不决定容量，容量始终按物品总数量计算。
- 同一 `ItemId` 可因最大堆叠限制形成多个堆叠。
- 容量不足、数量非法、物品定义无效时返回明确失败原因，不修改原状态。
- 世界拾取物只在背包添加成功后从世界移除；失败时保留原拾取物。

### 4.4 移除、使用与丢弃

- 移除或消耗物品后立即释放对应容量。
- 数量降为 0 的堆叠应从背包中删除，并清除指向该堆叠的快捷引用。
- 使用物品时，先确认物品效果可执行；效果执行成功后再扣除数量，避免失败时损失物品。
- 丢弃物品时，只有世界掉落物成功创建后才从背包扣除；若创建失败，背包保持不变。
- 第一版所有数量操作均要求为正整数。

## 5. UI 与交互设计

### 5.1 底部快捷物品栏

- 锚定于安全区域内的屏幕底部中央，不随分辨率直接使用固定屏幕坐标。
- 每个物品以正方形格子展示，内容至少包含图标和堆叠数量；数量为 1 时可隐藏数量文本。
- 最多显示 10 个物品格。建议对应数字键 `1` 至 `0`，输入绑定应由项目输入配置管理。
- 少于 10 个快捷项时，仅展示已有快捷项；编辑态拖拽时可显示空槽作为放置目标。
- 当背包内存在未显示在快捷栏中的物品，或快捷项超过当前可展示范围时，在末端显示展开按钮。按钮图标可使用三个点或向上箭头，最终视觉由 UI 稿确定。
- 点击展开按钮打开总背包面板；再次点击、点击关闭按钮或按取消键关闭。
- 快捷栏显示容量文本：`已使用 / 总容量`，例如 `18 / 30`。
- 当前选中的快捷项应有清晰高亮；不可使用的物品应有禁用反馈，但不改变其背包状态。

说明：首版快捷栏最多配置 10 项。若未来允许配置超过 10 项，应另行定义分页、滚动或替换规则，不能让第 11 项处于不可访问状态。

### 5.2 总背包面板

- 面板打开后展示玩家当前拥有的全部物品堆叠，不受 10 项限制。
- 采用可滚动的动态网格布局，格子尺寸保持一致。
- 面板应显示标题、容量文本 `已使用 / 总容量`、物品网格和关闭入口。
- 每个格子至少显示图标、数量；悬停或选中后显示名称、描述、单件容量及可执行操作。
- 物品变化时通过事件刷新相关格子和容量文本，不在 `Update` 中轮询整个背包。
- 面板打开时的游戏暂停策略沿用项目统一 UI/暂停规则，不由背包领域模型直接控制时间。

### 5.3 拖拽规则

| 起点 | 终点 | 结果 |
| --- | --- | --- |
| 背包物品 | 快捷栏空位 | 创建快捷引用 |
| 背包物品 | 快捷栏已有位置 | 替换该位置的快捷引用；被替换物品仍在背包 |
| 快捷栏物品 | 快捷栏另一位置 | 两个快捷项换位，或移动到空位 |
| 快捷栏物品 | 背包面板有效区域 | 取消该快捷引用，物品仍在背包 |
| 任意物品 | 无效区域 | 取消拖拽并恢复原 UI 状态 |

拖拽过程中显示物品图标跟随指针和有效/无效落点反馈。一次拖拽只修改快捷配置，不修改物品数量。触屏操作可在后续增加长按拖拽，但领域规则保持一致。

### 5.4 状态同步

- 背包内容是唯一事实来源，快捷栏和总背包面板都是其视图。
- 添加、移除、使用、丢弃或堆叠变化后，两处 UI 必须在同一事件链中刷新。
- 容量文本在两处显示相同值。
- 面板关闭后，底部快捷栏继续展示并可使用。

## 6. 反馈与异常状态

| 场景 | 系统行为 | 玩家反馈 |
| --- | --- | --- |
| 容量不足 | 拒绝整次添加 | 提示“背包容量不足”，可短暂强调容量文本 |
| 无效数量 | 拒绝操作并记录带上下文的开发日志 | 正常玩法中不应触发 |
| 物品配置缺失 | 拒绝添加或显示占位信息 | 开发期输出具体 `ItemId` |
| 快捷目标无效 | 恢复拖拽前状态 | 无效落点视觉反馈 |
| 物品已被消耗 | 清除失效快捷引用 | 快捷格消失或变为空位 |
| 重复快速操作 | 每次变更进行状态校验 | 不复制、不产生负数数量 |

## 7. 建议的技术设计

### 7.1 模块职责

- `Items/Definitions`：物品静态定义及稳定 ID。
- `Inventory/Domain`：纯 C# 的背包、堆叠、容量和不变量。
- `Inventory/Application`：拾取、使用、丢弃和快捷配置用例。
- `UI/Inventory`：快捷栏、总背包面板、格子视图与拖拽表现。
- `Bootstrap`：创建背包实例并将其注入拾取、使用和 UI 模块。

### 7.2 建议领域对象

- `ItemDefinition`：只读物品配置。
- `ItemStack`：`ItemId`、数量及稳定的运行时堆叠 ID。
- `Inventory`：维护堆叠集合、总容量和添加/移除规则。
- `InventoryOperationResult`：成功状态、失败原因及实际变化信息。
- `QuickBarConfiguration`：最多 10 个快捷位置到堆叠 ID 的引用。
- `InventoryPresenter` / `QuickBarPresenter`：订阅领域事件并驱动视图。

快捷栏引用稳定的运行时堆叠 ID，而非列表下标。堆叠合并、删除或载入存档时，应由应用层修复或清除无效引用。

### 7.3 公开行为建议

领域层至少提供以下语义能力，具体签名以实现时项目约定为准：

- 查询总容量、已使用容量和剩余容量。
- 预检查指定物品及数量能否完整加入。
- 原子添加物品并返回结果。
- 按堆叠或物品 ID 移除指定数量并返回结果。
- 提供只读堆叠视图，禁止外部直接修改集合与数量。
- 在内容或容量变化后发布一次明确事件。

不建议让 UI 直接操作 `List<ItemStack>`、直接设置数量，或自行计算容量。

## 8. 存档要求

为阶段 9 的存档功能预留以下数据：

- 背包总容量。
- 每个堆叠的稳定运行时 ID、`ItemId` 和数量。
- 10 个快捷位置对应的堆叠 ID。
- 存档数据版本号。

载入时必须重新校验物品定义、数量、容量和快捷引用。损坏或过期数据不得导致负数容量、超容量状态或空引用异常；具体迁移和恢复策略在存档设计中定义。

## 9. 验收标准

### 9.1 领域逻辑

- 背包可持有任意数量的物品种类和堆叠，直到总容量用尽。
- 多种物品、多个堆叠下的容量计算准确。
- 恰好填满剩余容量时添加成功；超过剩余容量时整次添加失败。
- 添加失败不会改变数量、堆叠、容量或世界拾取物。
- 添加优先补充已有堆叠，并正确处理跨多个堆叠的数量。
- 使用、移除和丢弃后容量正确释放，数量不会为负。
- 最后一个物品被移除后，对应快捷引用自动失效。

### 9.2 UI 与交互

- 快捷栏位于屏幕底部，在目标分辨率和安全区域内不遮挡、不越界。
- 快捷栏最多显示 10 个物品项，并在存在更多背包物品时显示展开按钮。
- 点击展开按钮后，总背包面板显示全部物品及正确数量。
- 两处均以 `已使用 / 总容量` 格式显示一致的容量。
- 背包与快捷栏之间拖拽可正确添加、替换、换位和取消快捷引用。
- 拖到无效区域后状态完全恢复，不复制、不丢失物品。
- 使用或移除物品后，两处 UI 同步更新。
- 鼠标和键盘流程可用；手柄与触屏不作为第一版验收项，除非项目输入目标调整。

### 9.3 测试建议

- Edit Mode：空背包、恰好装满、超容量、非法数量、堆叠边界、跨堆叠添加/移除、重复调用和快捷引用清理。
- Play Mode：打开/关闭面板、拖拽所有路径、容量文本同步、拾取失败保留世界物品、连续快速点击不重复消费。
- 手工验证：16:9、16:10、超宽屏和项目目标的最低分辨率；检查底部安全区、文本截断、滚动和拖拽反馈。

## 10. 待产品确认项

以下选择不阻碍领域层实现，但应在 UI 制作前确认：

1. 展开按钮最终使用“三个点”还是“向上箭头”。
2. 总背包面板打开时游戏继续、减速还是暂停。
3. 快捷栏是否允许同一物品堆叠被配置到多个快捷位置；本文默认不允许。
4. 物品排序采用获得顺序、类别、名称还是玩家手动顺序；本文默认保持获得顺序。
5. 拾取数量超过容量时是否继续保持“全部拒绝”；本文按需求默认全部拒绝，不做部分拾取。
6. 第一版是否需要手柄导航和触屏长按拖拽。

## 11. 完成定义

当领域规则的 Edit Mode 测试通过、UI 的 Play Mode 流程通过、目标分辨率手工验收完成，并且不存在物品复制、丢失、负数数量、容量不同步或失效快捷引用时，本功能可视为完成。
